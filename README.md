# INSY7314 ICE Task 2 – Secure Movie API

## 1. Project Overview

https://github.com/Sango-Tapiwa/INSY7314-ICE-Task-2.git 

This project is a structured backend API developed using **Node.js and Express.js** for **INSY7314 Information Systems 3D – ICE Task 2**.

For Activity 2, the original **Gadget** resource was changed to a **Movie** resource.

The Movie resource contains the following five attributes:

1. `id`
2. `title`
3. `genre`
4. `year`
5. `description`

The API stores movie information in a temporary in-memory JavaScript array. This means that any movies added through the POST endpoint will be removed when the server is stopped or restarted.

The backend includes:

* Express routes
* Controllers
* Middleware
* Input validation
* Controlled CORS
* Helmet security middleware
* Central error handling
* Temporary in-memory movie data
* Postman testing

# 4. Movie Resource

Each movie contains five attributes:

```text
id
title
genre
year
description
```

Example:

```json
{
  "id": "m1",
  "title": "Inception",
  "genre": "Sci-Fi",
  "year": 2010,
  "description": "A thief enters peoples dreams to steal secrets."
}
```

The `id` is automatically generated by the API when a new movie is created.

# 24. Security Features

The API includes several security and backend configuration features.

### Helmet

Helmet is used to add security-related HTTP headers.

### Controlled CORS

CORS is configured to allow requests from the configured client origin.

### JSON Body Limit

The JSON request body is limited to 10 KB.

### Disabled X-Powered-By

Express's `X-Powered-By` header is disabled.

### Central Error Handler

A central error handler is used to handle errors consistently across the API.

# 25. Temporary In-Memory Storage

The movie data is stored in a JavaScript array inside:

```text
controllers/movieController.js
```

The current collection contains:

```text
m1 – Inception
m2 – The Dark Knight
m3 – The Hangover
m4 – The Godfather
m5 – The Conjuring
m6 – Titanic
m7 – Spiderman
```

This is temporary storage and is not connected to a database.

When the server is restarted, newly added movies are removed and the original movies are restored.

Therefore, the five new movies should be added during the same server session when completing the Postman testing.
